# EasyEDA Schematic Failure Patterns

Read this reference only when a matching symptom appears or a prior failure is being reviewed. Apply the prevention to the affected block; do not turn one historical example into an unrelated global rewrite.

| Symptom | Likely cause | Prevention or correction |
|---|---|---|
| Circuit mode contradicts a page note | Notes or images were not enumerated before choosing a familiar configuration | Build a page-note constraint ledger before component selection and reconcile it again before save. |
| Blue text appears along ordinary wires | A non-empty internal `Wire.net` was used as invisible metadata | Create ordinary local wires with `net: ""` from the first call; use native visible labels only when needed. |
| GND name is hidden, duplicated, or far away | API-created flag presentation was assumed to match manual placement, or separate text was added | Query the native `Name`; keep it visible and owned by the flag. For a normal vertical flag, preserve default geometry when it renders correctly. |
| Side-facing GND is reversed or a wire crosses its body | Child graphics/text were adjusted independently, or only the label was inspected | Rotate or replace the parent flag as one object; verify pin direction, body direction, wire termination, and native name together in an enlarged render. |
| GND is readable but visibly off-center | Attribute coordinates or collision absence were mistaken for visual alignment | Compare rendered text bounds with the symbol axis or centerline and use the project-standard small gap. |
| Horizontal power labels are crooked, touch a stroke, or sit on different baselines | Mirrored parents use different anchors; coordinates or `alignMode` were copied between sides | Preserve each flag's working anchor mode and align from rendered glyph bounds. Match the user reference, including the inner-edge gap. |
| Circuit is sparse despite short individual segments | Global top/bottom or perimeter rails were laid out before pin-local groups | Group peripherals around IC pins and minimize complete functional loops. Replace long unrelated rails with local native flags when unambiguous. |
| One passive has visibly smaller labels | Library/API default `0.0675 inch` attributes were left inside a `0.1 inch` block | Query `Designator` and `Name` font sizes after placement; normalize SCH_AI passive labels to `0.1 inch` unless the reference specifies otherwise. |
| Diode or LED lead looks kinked | The first wire segment leaves the pin perpendicularly | Make the first segment collinear with the pin axis and turn farther away. |
| Diode or LED looks tidy but is electrically reversed | Rotation was chosen from appearance or copied from a reference page without checking anode/cathode pin mapping | Identify the polarized pins and intended current direction first, then verify the final saved rotation and both connected nets. For active-low sink indicators, place the anode toward the positive rail through its resistor and the cathode toward the sink output. |
| A harmless green lead is removed | Exposure or color was treated as a defect without considering topology | Judge the segment by connectivity, alignment, clearance, and composition; retain useful finite leads. |
| Designator/value crosses a wire or symbol | Routing began before owned-text bounds were reserved, or text alone was dragged during cleanup | Place/query parts first. Move the obstructing wire or whole owning object before adjusting text alone. |
| Values disappear after moving components | A partial `sch_PrimitiveComponent.modify` replaced `otherProperty`, clearing the hidden `Value` used by `Name = {Value}` | Do not use partial component modify as a move shortcut. Snapshot the complete component and owned attributes, use narrow attribute APIs where possible, and verify value, footprint, supplier, and datasheet fields immediately after every component mutation. |
| A before/after metadata audit falsely reports no change | The queried component object was reused as a live async state object, so the supposed before-state mutated in memory | Deep-clone the queried component and owned attributes before `toAsync()` or any setter. Compare the immutable snapshot with a fresh post-change query. |
| One recreated GND is correct but another is hidden or reversed | A successful representative instance was assumed to guarantee all later instances | Query and render every created or relocated GND individually. Verify native name visibility, body direction, pin endpoint, and saved appearance for each instance. |
| Problems are discovered only after delivery | QA relied on coordinates, sampled only some regions, or used a zoomed-out full-page image | Make a complete dense/changed-region checklist. Every item must pass a legible enlarged crop after its final mutation; any later nearby edit invalidates the earlier check. Inspect the full page only after all local gates pass. |
| A drawing looks broken immediately after a batch and correct later | The asynchronous editor/render state had not settled, so a stale intermediate frame was inspected | Requery the changed primitives and require two consecutive equivalent states for multi-object or merged-wire changes before inspecting and saving. Prefer Gateway render preview; use general computer control only if the render API is unavailable. |
| A user-created tiny connector is deleted and DRC worsens | Geometry was classified as junk without proving its editor/API connectivity role | Capture primitives and DRC before replacement; preserve native types and prove equivalent connectivity/render afterward. |
| An API retry duplicates or deletes unexpected objects | A failed execute batch was assumed atomic | Requery exact old/new IDs after every error; continue from actual state rather than replaying the whole batch. |
| Gateway attaches very slowly after startup or restart | EasyEDA v1.0.5 is scanning ports serially, repeated reconnects race the same registration, or the extension runtime is stale | Follow the single-reconnect and restart sequence in [easyeda-gateway.md](easyeda-gateway.md). Do not toggle the extension manager without explicit user request or evidence that it is disabled. |
